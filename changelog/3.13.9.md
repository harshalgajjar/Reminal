# 3.13.9

A big round of improvements to `reminal expose` — sharing a local app over a
link now works with far more apps, handles big files and live connections, and is
sturdier and safer.

Works with more of your apps
- Router, NAS and server admin panels now stay logged in. Signing in to
  webmin, UniFi and similar pages used to appear to work and then immediately
  forget you, over and over. Sign-in now sticks.
- Apps served over HTTPS just work. `reminal expose 8443` reaches a local
  HTTPS admin UI the same way it reaches a plain one — no extra flags.
- Apps that only answer on "localhost" now work. Plenty of dev servers start
  that way by default on a Mac and were unreachable before; every visitor got
  "local server unreachable" while the same page loaded fine in your own browser.
  reminal now finds them.
- Live connections work end to end. Dashboards, logs, terminals, chat and
  anything else that streams over a WebSocket now connect, stay connected, and
  close cleanly with a real reason when they end.

Big files and live data
- Upload and download large files through a link. Sizeable uploads and
  multi-megabyte pages and downloads now go through intact instead of dropping
  the connection.
- Live pages feel live. Streaming output (server-sent events, long-polling,
  live logs, progressive pages) reaches the browser promptly instead of lagging.
- You're warned if a shared file was too big to send whole, in the window you
  shared from, so a truncated download can't quietly look complete.

Sturdier and safer
- A shared link's PIN page stands up to abuse. A flood of sign-in guesses, an
  overly long or malformed request, or junk fired at the page from anywhere on
  the internet no longer knocks the link offline or slips past the try limit.
- Sign-in can't be tricked into sending you off-site. A crafted link could
  previously bounce you to another website right after you signed in; sign-in now
  only ever returns you to a page on the link itself.
- Apps that trust a visitor's IP can't be fooled about it. For an app that
  allow-lists, rate-limits or logs by IP, a visitor can no longer claim a
  different address — reminal supplies the real one and ignores any they assert.
- Redirects and links stay on the shared link instead of pointing a visitor
  at their own machine or asking for the PIN twice.

Clearer errors
- When something genuinely can't be passed on, you get a sentence explaining
  what happened — nothing listening, a dropped or timed-out connection, a reply
  reminal couldn't read — instead of a bare error code or a misleading "server
  unreachable" when your server is running fine.

On phones and tablets
- The on-screen keyboard for a window is now a toggle. The keyboard control
  above a window used to just raise the soft keyboard, and the next tap on the
  window put it away again — so typing into a remote text field meant tapping the
  field, watching the keyboard vanish, and reaching for the button once more. It
  now stays up until you turn it off, and remembers your choice.

Note for self-hosters: this release includes the matching relay update, so
everything above is live for links served through reminal.app.
